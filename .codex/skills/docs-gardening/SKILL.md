# Docs gardening

Treat code, schemas, tests, and verified runtime behavior as evidence. Find stale links, duplicated rules, obsolete workflows, contradictions, and docs that no longer match implementation.
Prefer deleting or linking over duplicating.
Keep indexes navigable and progressive: map first, detail on demand.
Never silently turn inference into documented fact.
When a rule can be mechanically enforced, recommend or add the check instead of expanding prose.
